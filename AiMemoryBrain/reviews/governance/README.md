# 治理类独立评审归档目录

## 1. 目录用途

`reviews/governance/` 用于归档本仓库治理变更相关的独立评审报告。

本目录保存对治理决策、治理规则、许可证变化、权利授予、风险等级和重大治理变更进行独立审查所形成的正式报告。

主要用途：

1. 保存独立评审的正式结论。
2. 记录评审对象及其精确版本。
3. 记录风险等级和评审依据。
4. 保存 PASS、PARTIAL、FAIL 等审查结果。
5. 登记问题编号、严重程度和整改要求。
6. 保留历史治理缺陷和事后补救记录。
7. 为后续决策和审计提供可复核依据。

本目录是治理审查证据的归档位置，不是原始决策记录的替代位置。

## 2. 适用范围

以下事项应当纳入本目录：

- 治理规则新增或修改。
- 许可证和权利授予变化。
- L3 风险治理变更。
- 治理决策记录的独立审查。
- 第三方许可和版权治理。
- 重大架构治理机制调整。
- 其他需要独立评审的治理事项。

普通代码评审、功能测试报告及日常实现说明不应仅因涉及治理关键词而自动归入本目录。

## 3. 文件命名规则

统一采用：

`REV-YYYY-MM-DD-NNN-<topic>.md`

字段说明：

| 字段 | 含义 |
|---|---|
| REV | 独立评审报告前缀 |
| YYYY-MM-DD | 评审日期 |
| NNN | 当日或对应编号空间中的三位序号 |
| topic | 简短、稳定、可识别的主题名称 |
| `.md` | Markdown 文件 |

示例：

`REV-2026-11-20-001-independent-review.md`

要求：

- 日期采用 ISO 风格。
- 序号不得随意重复。
- topic 使用小写英文和连字符。
- 文件名不得使用模糊的 `latest`、`final2` 等标识。
- 已归档报告不得通过覆盖文件的方式改写历史结论。

## 4. 精确版本绑定要求

每份正式评审报告必须绑定被评审对象的精确版本。

至少记录：

1. 仓库标识。
2. PR 或变更标识。
3. base SHA。
4. head SHA。
5. merge SHA（已经合并时）。
6. 评审时间。
7. 评审者独立性声明。

不得只使用以下信息作为评审对象标识：

- 分支名称。
- PR 标题。
- 可变的 tag 名称。
- `main` 或 `master` 等分支引用。
- `latest` 等动态标识。

如果评审对象在评审过程中发生变化，必须重新确认 base/head SHA，并明确新旧评审对象之间的关系。

已合并变更必须记录实际 merge SHA。

尚未合并的变更可以不填写 merge SHA，但必须明确标注未合并状态。

## 5. 独立性声明

独立评审必须明确评审者与原始变更作者之间的关系。

对于独立会话评审，应记录：

`A DIFFERENT SESSION — NOT THE AUTHOR`

该声明用于表明评审者不是原始变更作者会话。

但会话独立不自动证明评审内容正确。

评审报告仍须提供可复核的证据、具体判断和明确结论。

## 6. 评审依据

每份报告必须列出实际使用的治理依据。

适用时至少包括：

- `governance/N01-reuse-first-principle.md`
- `governance/N06-risk-tiered-decision-depth.md`
- 对应的正式决策记录。
- 权威治理仓库中的适用规则。

引用具体条款时应注明文件和章节或条款编号。

不得仅写「依据治理要求」而不说明具体来源。

## 7. 评审结果规范

正式评审必须给出明确结论。

采用以下结果：

| 结论 | 含义 |
|---|---|
| PASS | 证据满足适用要求 |
| PARTIAL | 部分满足，仍存在明确缺口 |
| FAIL | 不满足要求 |
| VERDICT: ACCEPT | 整体接受 |
| VERDICT: REVISE | 需要补正 |
| VERDICT: REJECT | 不接受 |

单项检查结果与整体评审结论应当分开。

不能因为多数检查项 PASS，就忽略具有阻断作用的 P1 问题。

## 8. 问题编号

评审问题采用：

`ITEM-NN`

每项必须包含：

- 编号。
- 严重程度。
- 问题描述。
- 证据依据。
- 影响。
- 建议处置。

严重程度采用：

- P1：重大治理缺陷。
- P2：重要治理缺陷。
- P3：一般改进事项。

同一报告内不得重复使用问题编号。

已经发布的评审报告不得通过删除问题编号改变原评审发现。

## 9. 事后评审的强制标注

**事后评审必须明确标注时序缺陷。**

如果被评审变更已经合并，而适用要求规定必须在合并前完成独立评审，评审报告必须明确说明：

1. 评审发生在合并之后。
2. 合并前是否存在独立评审证据。
3. 原有时序要求是否满足。
4. 哪些内容可以通过事后补充证据改善。
5. 哪些历史事实无法追溯补足。

必须明确：

**事后评审不能追溯改变历史时序事实。**

不得把事后评审写成合并前评审。

不得通过事后修改原始决策记录伪造合并前审批状态。

不得把补救完成描述成原始流程已经合规。

## 10. 报告归档要求

报告归档时必须：

1. 使用规定的文件命名格式。
2. 绑定精确 base/head/merge SHA。
3. 记录 Review ID。
4. 记录评审依据。
5. 保留完整问题清单。
6. 保留最终 VERDICT。
7. 记录是否为事后评审。
8. 记录无法追溯补足的历史事项。
9. 与对应 PR 或治理决策建立可追溯关系。

如果存在补正件，应保留原报告，并通过独立文件记录后续整改状态。

## 11. 历史证据保护

本目录中的报告属于治理审计记录。

已经归档的报告不得通过静默覆盖或删除问题内容改变历史判断。

报告需要纠正时，应当创建新的补充报告或修订说明，并明确关联原始 Review ID。

原报告中的事实、评审时点和时序判断必须保留。
